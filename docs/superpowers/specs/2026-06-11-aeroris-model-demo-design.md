# AeroRIS 模型 Demo 页面设计

## 背景

当前 AeroRIS 前端已经包含首页研究展示和 `/dataset` 数据集详情页。接下来新增一个模型运行 demo 页面，用于答辩展示 AeroCRIS 的任务输入、推理过程、阶段改进和最终输出。

该页面不接入真实模型后端，也不提供在线推理服务。它使用真实 AeroRIS 样例与预置演示结果，模拟一次模型运行过程，让答辩听众快速理解：

1. 无人机场景指代表达分割的输入和输出是什么。
2. CRIS baseline 在小目标、多实例和复杂空间关系上为什么会失败。
3. AeroCRIS Stage 1 和 Stage 2 TTA 分别改善了什么。
4. AeroRIS 中空目标拒识为什么是一个独立难点。

## 页面定位

页面定位为“答辩演示台”，不是模型产品后台，也不是完整在线 demo。它应服务现场讲述，重点是节奏清楚、状态可控、视觉可信。

页面建议路径为 `/demo`。首页导航和首屏行动按钮中增加“演示”入口，数据集详情页暂时不强制增加入口。

## 设计目标

1. 首屏即可完成一次模型演示，不需要滚动后才能理解页面用途。
2. 用固定 5 步流程讲清楚 AeroCRIS 的方法贡献。
3. 提供少量交互：选择样例、运行演示、手动切换阶段、切换结果视图。
4. 缺失数据先使用占位，但必须明确标注为“预置演示 / 待替换真实结果”。
5. 视觉语言延续当前 AeroRIS 网站：白底、深蓝、细线、真实无人机图像、克制卡片和表格。

## 页面结构

### 1. 顶部导航

导航延续当前站点风格：

- AeroRIS Demo 品牌标题。
- 返回首页。
- 数据集。
- 方法。
- 演示流程。
- 典型样例。

页面应与现有站点保持同一套 header 视觉，不引入新的导航系统。

### 2. 首屏演示台

首屏采用三栏结构：

左侧：Demo Script

- 5 个固定样例入口。
- 当前样例的自然语言表达。
- “运行演示”按钮。
- “预置结果演示，未接入在线模型后端”的状态说明。

中间：模型推理现场

- 主图区域展示当前样例。
- 支持结果视图切换：Original、GT / Union Mask、CRIS baseline、Stage 1、Stage 2 TTA、Overlay。
- 自动播放时主图和缩略结果随阶段变化。

右侧：Presenter Notes

- 当前阶段的答辩讲解词。
- 当前样例的观察重点。
- 当前阶段对应的论文方法点，例如训练侧监督修正、Tiny Target Activation、空目标拒识。

### 3. 阶段对比

首屏下方提供简洁的阶段解释区，避免重复论文中的大表格。

内容包括：

- CRIS baseline：速度快，但小目标响应弱，容易漏检或局部分割。
- Stage 1：训练侧监督修正，通过面积保持、前景均衡、小目标加权和数量一致性辅助改善监督。
- Stage 2 TTA：推理侧轻量残差校准，增强目标区域激活并抑制背景响应。

该区块可以配合论文已有 Stage 1、Stage 2 和 AeroCRIS 框架图，但不应堆叠过多大图。首屏已经承担主要演示功能。

### 4. 典型样例库

样例库固定展示 5 个样例，每个样例对应一个答辩论点：

1. 小目标单实例：使用当前已有 `test-3003`，强调小目标面积小、baseline 易漏检。
2. 多实例集合：使用 `train-8522`，说明同一表达指向多个目标，union mask 合并实例监督。
3. 空间关系表达：使用 `test-2895`，说明空间词决定目标选择。
4. 高密度目标：使用 `train-8104`，说明密集目标和大量实例带来的分割压力。
5. 空目标拒识：暂时使用 empty mask 占位，后续替换为真实空目标样例。

样例卡片应展示：

- 样例类型标签。
- 原图或占位图。
- 表达文本。
- 观察重点。
- 当前资产状态：真实样例 / 预置结果 / 待替换。

### 5. 关键指标提示

页面末尾或阶段对比区附近展示少量关键指标：

- CRIS baseline：Test mIoU 17.82，Test oIoU 24.41，Latency 12.34ms。
- AeroCRIS Stage 1：Test mIoU 34.22，Test oIoU 38.61，Latency 12.52ms。
- AeroCRIS Stage 2 TTA：Test mIoU 36.76，Test oIoU 41.11，Latency 15.57ms，FPS 64.21。

这些指标用于支撑答辩演示，不再复刻完整论文表格。

## 5 步运行流程

点击“运行演示”后，页面按固定节奏播放 5 个状态。每个状态持续约 1.0 到 1.4 秒，总时长控制在 6 到 8 秒。用户也可以手动点击阶段节点停留。

### Step 1：输入任务

展示原始无人机图像和表达文本。右侧讲解任务定义：输入图像和自然语言表达，输出表达所指目标的像素级二值 mask。

### Step 2：CRIS baseline

展示 baseline 预测结果或占位预测结果。右侧说明 baseline 的主要问题：小目标响应弱、多实例覆盖不完整、复杂背景中容易误激活。

### Step 3：Stage 1

展示 Stage 1 预测结果或占位结果。右侧说明训练侧监督修正的作用：通过小目标加权、前景均衡和数量一致性辅助，使模型更重视低空小目标。

### Step 4：Stage 2 TTA

展示 Stage 2 TTA 预测结果或占位结果。右侧说明 Tiny Target Activation 在推理阶段对 logits 做轻量残差校准，增强目标区域并抑制背景。

### Step 5：最终输出

并列展示 GT / CRIS baseline / AeroCRIS Stage 2 TTA。右侧给出一句样例级结论，例如“Stage 2 后目标区域更完整，背景误响应减少”。

## 交互行为

### 样例选择

点击样例卡片后：

- 更新表达文本。
- 更新主图、GT、overlay 和预测结果。
- 将阶段重置到 Step 1。
- 清除自动播放计时器。

### 运行演示

点击“运行演示”后：

- 阶段从 Step 1 自动推进到 Step 5。
- 当前阶段节点高亮。
- 主图和右侧讲解同步变化。
- 播放结束后停留在 Step 5。

### 手动阶段切换

点击阶段节点后：

- 停止自动播放。
- 切换到对应阶段。
- 保持当前样例不变。

### 结果视图切换

结果视图用于补充观察，不替代 5 步流程。建议视图包括：

- Original
- GT
- CRIS
- Stage 1
- Stage 2
- Overlay

如果当前阶段没有真实图像，则展示占位视觉和“待替换真实结果”标记。

## 数据与占位策略

### 已有真实资产

可以复用当前项目中的真实 AeroRIS 样例资产：

- `public/assets/aeroris-dataset/images/*`
- `public/assets/aeroris-dataset/union_masks/*`
- `public/assets/aeroris-dataset/visualizations/*`
- `public/assets/aeroris-dataset/instance_masks/*`

这些资产可用于 Original、GT / Union Mask、Overlay 和部分实例说明。

### 缺失预测结果

当前项目尚未整理单样例的 CRIS baseline、Stage 1 和 Stage 2 TTA 预测图。实现阶段使用占位结果：

- 用半透明 mask、热力图式占位或黑底白色 mask 占位表现。
- 明确显示 `预置演示结果` 或 `待替换真实预测`。
- 后续真实预测图补齐后，只需要替换数据配置中的图片路径。

### 空目标拒识

空目标拒识保留为第 5 个样例。实现阶段先使用：

- 当前无人机图像或中性占位图。
- 黑底 empty mask。
- 文字说明：“该样例用于展示空目标拒识，真实空目标样例后续替换。”

不应将该占位伪装为真实推理结果。

### 数据结构建议

新增 demo 数据配置，建议包含：

- `id`
- `title`
- `category`
- `expression`
- `image`
- `gtMask`
- `overlay`
- `baselinePrediction`
- `stage1Prediction`
- `stage2Prediction`
- `isPlaceholder`
- `assetStatus`
- `observation`
- `stageNotes`

后续替换真实数据时优先更新数据配置，不改组件结构。

## 文案原则

页面文案偏答辩讲解，而不是产品营销。

推荐使用：

- “当前为预置结果演示，未接入在线模型后端。”
- “该占位将替换为真实 CRIS baseline 预测结果。”
- “Stage 1 主要改变训练监督，不增加部署阶段计算。”
- “Stage 2 TTA 在推理阶段进行轻量残差校准。”

避免使用：

- “实时推理已完成。”
- “上传任意图片并运行模型。”
- “在线生成预测结果。”
- 任何暗示已经接入真实后端的说法。

## 响应式设计

桌面端：

- 首屏使用三栏结构。
- 左侧样例列表固定宽度，中间图像区域最大化，右侧讲解宽度稳定。
- 阶段节点可以横向排列。

平板和移动端：

- 三栏改为单列。
- 样例选择变成横向滚动或紧凑按钮组。
- 主图在表达和运行按钮之后出现。
- Presenter Notes 放在主图下方。
- 阶段节点可改为横向滚动或垂直列表。

所有中文文本、按钮和标签必须避免溢出容器。

## 技术范围

实现继续使用当前 Vite + React + TypeScript 项目，不引入路由库。根据当前项目模式，可通过 `window.location.pathname === '/demo'` 渲染 demo 页面。

建议新增或调整：

- `content.ts`：新增 demo 数据配置。
- `App.tsx`：新增 `DemoPage`、demo 控件和阶段展示组件。
- `App.css`：新增 demo 页面样式，复用现有色彩、header、按钮和图像样式。
- `App.test.tsx`：新增 `/demo` 页面渲染、5 步流程、占位标记和导航入口测试。

## 验证要求

实现完成后需要：

1. `npm test` 通过。
2. `npm run build` 通过。
3. 浏览器打开 `/demo`，确认首屏三栏结构、样例选择、运行演示、阶段高亮和占位标记正常。
4. 浏览器检查首页是否存在“演示”入口并能进入 `/demo`。
5. 检查桌面端无横向溢出。
6. 检查移动视口下三栏能正确堆叠，按钮和中文文本不溢出。

## 已确认决策

- 页面定位：答辩展示型模型 demo。
- 后端：不接真实模型服务。
- 演示流程：固定 5 步。
- 样例数量：5 个。
- 空目标拒识：保留，先占位，后续替换真实样例。
- 缺失预测结果：先占位，后续替换真实数据。
- 页面声明：必须明确标注预置演示和未接后端。

## 不纳入当前范围

- 用户上传任意图片。
- 自由文本输入后实时生成预测。
- 在线模型推理 API。
- 账号系统、下载系统、任务队列或服务端存储。
- 完整 benchmark 排行榜。
