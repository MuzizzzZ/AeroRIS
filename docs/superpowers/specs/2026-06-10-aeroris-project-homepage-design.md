# AeroRIS 中文公开研究项目主页设计

## 背景

用户希望参考 `https://uav-dualcog.lozumi.com/` 的设计风格和设计思路，为毕业论文《面向低空智能感知的无人机场景指代表达理解方法研究》制作一个前端页面。页面定位为公开项目主页/作品集式研究成果展示，而不是答辩网页或论文目录复刻。

当前工作区 `/Users/hozeeric/Desktop/AeroRIS` 为空目录，非 Git 仓库。论文 Word 文件位于 `/Users/hozeeric/Desktop/2207030223-李泓哲-面向低空智能感知的无人机场景指代表达理解方法研究.docx`。实现阶段可以从该 Word 中提取论文图像和关键数据，用于页面内容。

## 设计目标

页面采用中文为主的公开研究项目主页。它需要让访问者在几分钟内理解：

1. AeroRIS 研究解决什么问题。
2. 数据集为什么具有低空无人机场景特色。
3. 基准模型在哪些切片上失败。
4. AeroPlug / AeroCRIS 如何在实时约束下提升指代分割效果。
5. 当前工作的局限和后续方向。

保留英文研究名词和指标，例如 AeroRIS、AeroPlug、AeroCRIS、CRIS、TTA、mIoU、oIoU、Pr@0.7、FPS 等。其余导航、段落、说明、按钮和图表标题默认使用中文。

## 视觉方向

视觉参考 UAV-DualCog 的学术项目官网风格：

- 白底、深蓝正文、细分隔线、低饱和灰蓝辅助色。
- 标题使用强烈的学术衬线气质，正文和导航使用清晰的无衬线字体。
- 首屏左侧放研究总览图或方法框架图，右侧放项目名、论文题目式说明和占位按钮。
- 用数据卡、表格、方法矩阵和样例对比建立可信度。
- 动效克制：首屏淡入、导航锚点平滑滚动、图表/样例区域轻量悬停或进入动效。

需要避免：

- 科技感过强的深色大渐变背景。
- 把论文七章机械搬成七个页面区块。
- 大量装饰性卡片、夸张阴影、营销式 hero。
- 复杂筛选器、完整排行榜应用或多页面站点。

## 内容结构

### 1. 首屏

首屏的主标题为 `AeroRIS`。副标题为中文研究定位，例如：

> 面向低空智能感知的无人机场景指代表达理解与像素级分割研究。

视觉锚点优先使用论文中的研究路线图或 AeroCRIS 总体框架图。首屏下方展示四个核心数据：

- 17,882 条表达
- 8,536 张唯一图像
- AeroCRIS Test mIoU 36.76
- 15.57ms/query 单查询延迟

### 2. 研究概览

解释低空无人机指代表达理解的任务价值，重点描述：

- 目标小，容易在下采样或分割中消失。
- 同类实例密集，空间词和数量词是关键线索。
- 表达可能指向多个实例或空目标。
- 低空在线感知需要兼顾精度和实时性。

这一节使用短段落和问题卡片，而不是长论文式文本。

### 3. AeroRIS 数据集

展示 AeroRIS 的任务定义和数据统计：

- 输入：低空无人机图像 + 自然语言表达。
- 输出：表达所指对象的二值分割掩码。
- 多实例表达输出 union mask。
- 空目标表达输出空掩码。

核心统计来自论文：

- train 13,022 条表达
- val 1,428 条表达
- test 3,432 条表达
- total 17,882 条表达
- 总唯一图像 8,536
- 空标注 846
- union mask 17,036
- instance mask 63,557

展示数据难点：

- area < 0.1% 的测试样本 457 条。
- area 0.1%-0.5% 的测试样本 1,612 条。
- 测试集中 6 个以上实例样本 650 条。
- 测试集中关系表达 2,755 条，复数或集合表达 2,128 条。

### 4. 基准评测

用简化表格或图表展示主要模型表现。核心比较包括：

- ReLA：Test mIoU 50.48
- CoHD：Test mIoU 49.12
- CADFormer：Test mIoU 47.20
- RMSIN：Test mIoU 45.68
- RsRefSeg：Test mIoU 43.55
- LAVT：Test mIoU 31.80
- ASDA：Test mIoU 28.09
- CRIS：Test mIoU 17.82

同时展示精度与效率权衡：

- CRIS 原始速度快，但精度低。
- ReLA、CoHD、CADFormer 等模型精度更高，但成本更大。
- 这解释了为什么论文选择 CRIS 作为轻量化改进 baseline。

### 5. AeroPlug / AeroCRIS 方法

这一节解释方法，而不是堆公式。使用流程图式结构：

- Stage 1：训练侧监督修正。
  - 面积保持式目标监督。
  - 前景均衡 BCE 与 Dice 联合监督。
  - 小目标加权分割损失。
  - 数量一致性辅助建模。
- Stage 2：Tiny Target Activation。
  - 轻量残差校准。
  - 坐标图、深度可分离卷积、ECA 轻量注意力。
  - 增强非空目标区域激活。

核心结果：

- CRIS baseline：mIoU 17.82，oIoU 24.41，延迟 12.34ms/query。
- AeroCRIS Stage 1：mIoU 34.22，oIoU 38.61，延迟 12.52ms/query。
- AeroCRIS Stage 2 TTA：mIoU 36.76，oIoU 41.11，延迟 15.57ms/query。

需要明确说明 Stage 1 的数量辅助头推理阶段不参与前向传播，因此部署 FLOPs 和参数量与 CRIS baseline 基本保持一致。

### 6. 样例对比

借鉴参考站 Task Examples，但保持轻量。展示 2-3 个典型样例：

- 小目标漏检改善。
- 多实例集合覆盖改善。
- CRIS baseline 的严重错配或 under-segment 对比。

每个样例包含：

- 原图或论文中已有可视化图。
- 表达文本。
- GT。
- CRIS。
- AeroCRIS。

如果实现阶段无法可靠拆出单个样例图片，则使用论文现有综合可视化图作为图片主体，旁边配中文解读。

### 7. 局限与展望

这一节从论文第 7 章提炼：

- 空目标拒识仍然困难，TTA 增强非空目标时会降低 empty correct。
- Pr@0.9 等高阈值指标仍低，边界精细度需要提升。
- 后续可扩展复杂天气、夜间、动态场景。
- 可探索基础模型候选生成与端到端轻量模型的混合架构。
- 可接入低空无人机视频流评估连续帧稳定性和实时交互延迟。

## 技术范围

建议实现为一个本地可运行的前端项目。由于当前工作区为空，实施阶段可以选择轻量方案：

- Vite + React + TypeScript。
- CSS 使用普通 CSS 或 CSS Modules，避免引入复杂 UI 框架。
- 图标使用 lucide-react。
- 动效可用 CSS transition 或 Framer Motion；若依赖成本过高，优先用 CSS。
- 从 Word 中提取图片到项目 `public/assets` 或 `src/assets`，并只选最有代表性的图。

页面必须响应式适配桌面和移动端。移动端导航可简化为横向滚动锚点或折叠菜单，首屏改为单列布局。

## 验证要求

实现完成后需要：

1. 启动本地开发服务器并给出访问 URL。
2. 在浏览器中检查桌面视口，确认首屏、导航、数据卡、图表和图片渲染正常。
3. 检查移动视口，确认中文标题和按钮不溢出。
4. 确认所有占位按钮不会跳到无效外链。
5. 运行项目可用的 lint/build/test 命令；如果没有测试命令，至少运行 build。

## 已确认决策

- 页面定位：公开项目主页/作品集式研究展示。
- 页面语言：中文为主，英文研究名词保留。

- 外链：先占位，后续再细化。
